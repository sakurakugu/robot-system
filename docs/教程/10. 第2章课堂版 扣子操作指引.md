# 第 2 章课堂版 扣子操作指引

## 使用目标

这份文档是给老师和学生直接照着操作的版本，目标只有一个：

在扣子里做出一个最简单的“机器狗动作翻译助手”。

它只负责把中文命令转换成 JSON，不负责真正控制机器狗。

## 本节课完成效果

学生输入：

```text
让机器狗站起来，然后向前走两步
```

机器人输出：

```json
{
  "actions": [
    {"action": "stand"},
    {"action": "forward", "steps": 2}
  ]
}
```

## 上课前老师要准备什么

1. 确保学生可以正常访问扣子
2. 确保每个学生有可登录账号
3. 先由老师自己完成一次完整配置
4. 准备 5 到 6 条测试口令

## 学生操作流程

### 第一步：新建一个智能体

让学生在扣子中创建一个新的机器人。

机器人名称建议统一，例如：

```text
机器狗动作翻译助手
```

这样课堂里更容易统一说明。

### 第二步：写角色设定

让学生把下面这段话直接复制进去：

```text
你是一个机器狗动作翻译助手。

你的任务是把用户输入的中文命令转换成 JSON。

你只能使用这些动作：
- stand
- sit
- forward
- backward
- turn_left
- turn_right

输出要求：
1. 只能输出 JSON
2. 必须使用 {"actions": [...]} 结构
3. forward 和 backward 可以带 steps 参数
4. turn_left 和 turn_right 可以带 angle 参数
5. 如果一句话里有多个动作，按顺序输出
6. 不要输出 markdown 代码块
7. 不要输出解释，不要输出多余文字
```

### 第三步：添加几组示例

如果扣子支持示例对话，建议加入下面几组。

示例 1：

用户输入：

```text
站起来
```

期望输出：

```json
{"actions":[{"action":"stand"}]}
```

示例 2：

用户输入：

```text
坐下
```

期望输出：

```json
{"actions":[{"action":"sit"}]}
```

示例 3：

用户输入：

```text
向前走两步
```

期望输出：

```json
{"actions":[{"action":"forward","steps":2}]}
```

示例 4：

用户输入：

```text
向左转一下
```

期望输出：

```json
{"actions":[{"action":"turn_left","angle":30}]}
```

示例 5：

用户输入：

```text
站起来，然后向前走一步，再坐下
```

期望输出：

```json
{"actions":[{"action":"stand"},{"action":"forward","steps":1},{"action":"sit"}]}
```

### 第四步：开始测试

建议学生依次测试下面几句：

```text
站起来
坐下
向前走两步
向后退一步
向右转一下
站起来，然后向前走一步，再坐下
```

## 老师上课时要强调什么

### 强调 1：AI 不是在“瞎回答”

这里不是普通聊天，而是在做“中文 -> JSON”的转换。

### 强调 2：输出必须稳定

哪怕 AI 很聪明，如果今天这样输出、明天那样输出，程序就不好接。

### 强调 3：动作数量先少一点

动作少一点，成功率更高，也更容易讲清楚。

## 常见问题和现场处理

### 问题 1：输出前面总有一句解释

处理方法：

- 把“不要输出解释，不要输出多余文字”单独写成一条
- 再补 2 到 3 个标准示例

### 问题 2：把“站起来”写成了别的动作名

处理方法：

- 再次强调“只能使用给定动作”
- 给动作白名单

### 问题 3：一句复杂命令顺序错了

处理方法：

- 在要求里明确写“多个动作按顺序输出”
- 给一条多动作示例

## 这一节课的验收标准

只要学生能做到下面三点，就算通过：

1. 输入一句中文时，能输出 JSON
2. 输出里只有规定动作名
3. 多动作时顺序基本正确

## 本节课结束时要引到哪里

最后告诉学生：

现在我们已经有了“动作清单”，下一步要做的，就是让 Python 自己去拿这份清单，而不是每次都在网页里看。
