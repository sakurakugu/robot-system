# 老师讲课稿

## 适用场景

这份讲课稿适合带已经有基础 Python 能力的中小学生，用 1 到 2 节课快速跑通“AI 控制机器狗”的最小项目。

## 开场怎么讲

可以先直接讲一句话：

今天我们不是单纯写聊天机器人，也不是单纯控制机器狗，我们要把两件事接起来，让 AI 听懂人话，再让机器狗把动作做出来。

然后马上给学生看最终流程：

```text
一句中文
  ↓
AI 理解
  ↓
动作 JSON
  ↓
Python 程序
  ↓
机器狗执行
```

## 第一部分怎么讲

先问学生一个问题：

如果我对机器狗说“向前走两步”，机器狗能直接听懂中文吗？

让学生回答后，再总结：

- 机器狗本身不懂中文
- 程序也不适合直接处理模糊的人话
- 所以我们需要 AI 把中文翻译成结构化动作数据

## 第二部分怎么讲 JSON

不要一开始讲抽象定义，直接把 JSON 说成“动作清单”。

例如：

```json
{
  "actions": [
    {"action": "stand"},
    {"action": "forward", "steps": 2}
  ]
}
```

可以这样解释：

- `actions` 就是动作列表
- `stand` 表示站起来
- `forward` 表示前进
- `steps` 表示前进几步

## 第三部分怎么讲 AI 和 Python 的分工

建议反复重复一句话：

- AI 负责理解
- Python 负责执行

可以举例：

用户说：

```text
让小狗先站起来，再向左转一下
```

AI 做的事情是：

- 看懂这句话
- 输出动作列表

Python 做的事情是：

- 调用 AI
- 拿到 JSON
- 逐条执行动作

## 第四部分怎么讲“为什么要分阶段”

可以直接举调试例子：

如果最后机器狗没动，问题可能出在：

1. AI 没理解对
2. JSON 格式不对
3. Python 没解析对
4. 机器狗 SDK 没连上

所以要拆开学：

1. 先测 AI
2. 再测 Python
3. 再测机器狗
4. 最后再合并

## 上机环节建议

### 第一步

先运行：

```bash
python 01_ai_cli.py
```

让学生输入几句中文，观察输出 JSON。

### 第二步

再运行：

```bash
python 02_dog_demo.py
```

先看固定动作序列。

### 第三步

最后运行：

```bash
python 03_ai_control_dog.py
```

把前两部分连起来。

## 如果现场要连真实机器狗

建议老师先自己设置一组保守参数：

```text
DOG_CONTROL_MODE=project_executor
DOG_CONFIRM_BEFORE_RUN=true
DOG_FORWARD_SPEED=0.15
DOG_BACKWARD_SPEED=0.15
DOG_TURN_YAW_RATE=0.4
DOG_STEP_SECONDS=0.8
DOG_MAX_STEPS=2
DOG_MAX_ANGLE=45
```

这样学生即使输入“前进很多步”，执行层也会自动限制。

## 课堂中要不断提醒的事

### 提醒 1

不要把 AI 当成魔法，它只是把人话翻译成程序能读懂的格式。

### 提醒 2

程序最重要的不是“会不会聊天”，而是输入和输出是否稳定。

### 提醒 3

真实硬件调试一定要慢一点、短一点、保守一点。

## 课堂收尾怎么讲

最后可以让学生总结三句话：

1. AI 可以把自然语言变成结构化数据
2. Python 可以把结构化数据变成真实动作
3. 机器人项目要学会分层调试

如果学生能说清楚这三句，这节课就达成目标了。
