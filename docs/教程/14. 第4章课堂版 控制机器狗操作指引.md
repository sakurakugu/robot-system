# 第 4 章课堂版 控制机器狗操作指引

## 本章目标

这一章先不接 AI，只做一个固定动作演示，确认机器狗控制链路没问题。

## 本章完成效果

运行：

```bash
python 02_dog_demo.py
```

程序按顺序输出动作。

如果已经接上真实机器狗执行环境，机器狗会按顺序完成动作。

## 教学建议

第一次上课建议默认使用：

```text
DOG_CONTROL_MODE=dry_run
```

先让学生看见动作执行流程，再决定是否切到真实机器狗。

## 课堂操作步骤

### 第一步：确认当前模式

检查 `.env` 或环境变量中的：

```text
DOG_CONTROL_MODE
```

推荐：

- 课堂演示：`dry_run`
- 老师设备实操：`project_executor`

### 第二步：运行固定动作脚本

```bash
python 02_dog_demo.py
```

### 第三步：观察输出

程序会依次输出：

1. `stand`
2. `forward`
3. `turn_left`
4. `sit`

## 如果切换到真实执行模式

PowerShell 示例：

```powershell
$env:DOG_CONTROL_MODE="project_executor"
$env:DOG_CONFIRM_BEFORE_RUN="true"
python .\02_dog_demo.py
```

## 老师现场要强调什么

### 强调 1：这一步是在测“控制链路”

不是测 AI。

### 强调 2：固定动作最适合排错

因为固定动作不会受 AI 输出波动影响。

### 强调 3：真实机器狗要用保守参数

第一次动作必须短一点、慢一点。

## 常见问题

### 问题 1：程序能跑，但机器狗不动

说明程序层可能没问题，先检查：

1. 是否真的切到了 `project_executor`
2. SDK 依赖是否齐全
3. 机器狗网络是否正常

### 问题 2：切到 `project_executor` 后启动失败

先检查：

1. 是否在 Linux 环境
2. `robot-agent` 相关依赖能否导入
3. SDK 动态库是否存在

## 本章验收标准

只要学生能理解下面这件事，就算本章成功：

固定动作能跑通，说明机器狗执行链路是独立可测的。
