# 教程计划

## 一、教程目标

该教程面向已经有 Python 基础的中小学生，目标是带他们完成一个最小可运行项目：

`学生输入一句话 -> AI 理解成动作指令 -> Python 程序调用机器狗 SDK -> 机器狗执行动作`

## 二、学习目标

学完后，学生应该能做到：

1. 知道 AI 可以把“人话”转换成程序能理解的结构化数据
2. 会在扣子中体验一个简单的机器狗助手
3. 会用 Python 写一个 CLI 程序调用 AI
4. 会用 Python 调用机器狗 SDK 执行动作
5. 会把 AI 输出和机器狗动作连接起来

## 三、总实现思路

打算采用四阶段路线，而不是一上来就直接做 AI 控狗。

### 阶段 1：先体验扣子

目标：先建立“AI 可以理解指令并输出固定格式结果”的直觉。

本阶段内容：

- 认识什么是智能体
- 在扣子里创建一个简单机器人
- 给机器人一个明确任务：把自然语言转换成动作 JSON
- 测试几条简单命令

本阶段输入输出示例：

输入：

```text
让机器狗向前走两步
```

输出：

```json
{ "action": "forward", "steps": 2 }
```

本阶段验收标准：

- 学生能在扣子中输入一句命令
- 机器人能返回固定格式的 JSON
- JSON 中只包含预设动作，不出现自由发挥内容

### 阶段 2：Python CLI 调用 AI

目标：离开图形界面，用 Python 自己写程序调用 AI。

本阶段内容：

- 安装依赖
- 配置 API Key
- 用 Python 接收用户输入
- 调用 AI 接口
- 输出 AI 返回结果

建议只支持少量基础动作：

- `stand`
- `sit`
- `forward`
- `backward`
- `turn_left`
- `turn_right`

本阶段验收标准：

- 运行 `python main.py`
- 输入一句自然语言
- 程序输出标准 JSON 或动作列表

示例：

```json
[{ "action": "stand" }, { "action": "forward", "steps": 2 }]
```

### 阶段 3：单独打通机器狗 SDK

目标：不接 AI，先确认 Python 能直接控制机器狗。

本阶段内容：

- 配置机器狗连接环境
- 编写最小 Python 控制脚本
- 测试站立、前进、转向、坐下等动作
- 观察动作执行结果

建议设计一个固定动作演示脚本，例如：

1. 站立
2. 前进一步
3. 左转一次
4. 坐下

本阶段验收标准：

- 运行固定脚本后，机器狗能按顺序完成动作
- 学生知道问题可能出在网络、SDK 或动作参数，而不是 AI

### 阶段 4：AI 控制机器狗

目标：把前面两条链路合并成完整闭环。

执行流程：

1. 学生在命令行输入一句自然语言
2. Python 调用 AI
3. AI 输出动作 JSON
4. Python 解析 JSON
5. Python 根据动作名调用机器狗 SDK
6. 机器狗执行动作

本阶段验收标准：

- 输入一句简单中文命令
- AI 能输出合法动作数据
- 程序能把动作映射到 SDK
- 机器狗可以执行

## 四、教程章节设计

建议把正式教程拆成 6 章，每章都要有明确的“完成效果”和“动手练习”。

### 第 1 章：我们要做什么

目标：

- 让学生知道最终项目长什么样
- 先看到完整流程图和效果图

建议内容：

- 什么是机器狗
- 什么是 AI 控制
- 最终项目演示
- 整体流程图

本章完成效果：

- 学生能说清楚整个项目的 4 个环节：输入、AI、Python、机器狗

### 第 2 章：先用扣子做一个机器狗助手

目标：

- 不写代码，先体验 AI 输出结构化结果

建议内容：

- 创建智能体
- 编写简单提示词
- 约束 AI 只输出 JSON
- 测试 5 到 6 条常见命令

本章完成效果：

- 学生能得到固定格式动作结果

动手练习建议：

- 试着输入“站起来”“向前走两步”“向左转”

### 第 3 章：用 Python 写一个 AI 命令行助手

目标：

- 把扣子里的体验迁移到自己的 Python 程序中

建议内容：

- 安装依赖
- 配置环境变量
- 编写最小 CLI
- 打印 AI 返回内容
- 把返回结果解析成 Python 数据结构

本章完成效果：

- 学生可以在终端里输入一句中文并得到动作列表

动手练习建议：

- 增加一个“退出程序”命令
- 输入不同描述方式，观察 AI 是否仍能输出标准动作

### 第 4 章：用 Python 控制机器狗

目标：

- 学生先掌握“直接控制硬件”的最小方法

建议内容：

- 连接机器狗
- 调用 SDK
- 封装几个最基础动作函数
- 跑一个固定动作脚本

本章完成效果：

- 机器狗能执行 Python 中写死的动作序列

动手练习建议：

- 修改动作顺序
- 把前进一步改成前进两步

### 第 5 章：让 AI 来控制机器狗

目标：

- 完成从自然语言到真实动作执行的闭环

建议内容：

- 定义动作数据格式
- 建立动作映射表
- 做合法性检查
- 按顺序执行动作
- 打印执行日志

本章完成效果：

- 学生可以输入一句自然语言，机器狗按理解结果执行

动手练习建议：

- 试试“站起来后向右转再坐下”
- 观察 AI 输出动作顺序是否正确

### 第 6 章：做一个自己的小项目

目标：

- 给学生留出自由发挥空间

建议方向：

- 表演动作小狗
- 迎宾小狗
- 语音控制小狗
- 定时巡逻小狗

本章完成效果：

- 学生能在已有最小框架上做一个小改造

## 五、技术方案建议

为了降低教学复杂度，建议主动做几项限制。

### 1. 动作集合要小

建议第一版只保留这些动作：

- `stand`
- `sit`
- `forward`
- `backward`
- `turn_left`
- `turn_right`

如果机器狗 SDK 比较稳定，也可以额外增加：

- `shake_hand`
- `bow`

### 2. AI 输出必须固定格式

建议统一要求 AI 只输出 JSON，不输出解释文字。

推荐格式：

```json
{
  "actions": [{ "action": "stand" }, { "action": "forward", "steps": 2 }]
}
```

这样做的好处：

- Python 更容易解析
- 学生更容易理解数据结构
- 后续排错更简单

### 3. 不做复杂 Agent

第一版教程不要加入以下内容：

- 多轮记忆
- 自主规划
- 视觉识别
- 语音识别
- 自动避障
- 长链路任务编排

原因很简单：这些内容一旦混进第一版教程，难点会从“编程理解”变成“系统调试”。

### 4. 先做单轮指令

第一版只做：

- 输入一句话
- 输出一组动作
- 执行一次

不要一开始就做持续对话式控制，否则学生很容易把问题混在一起。

## 六、建议准备的素材

在开始正式写教程前，最好先准备好这些内容。

### 1. 一套最小示例代码

建议至少有 3 个脚本：

- `01_ai_cli.py`
- `02_dog_demo.py`
- `03_ai_control_dog.py`

这样每章都能直接对应一个可运行示例。

### 2. 一份动作映射表

这是整个教程里最关键的桥梁。

建议表格如下：

| 中文指令 | AI 动作名    | Python 执行函数    |
| -------- | ------------ | ------------------ |
| 站起来   | `stand`      | `dog.stand()`      |
| 坐下     | `sit`        | `dog.sit()`        |
| 向前走   | `forward`    | `dog.forward()`    |
| 向后走   | `backward`   | `dog.backward()`   |
| 向左转   | `turn_left`  | `dog.turn_left()`  |
| 向右转   | `turn_right` | `dog.turn_right()` |

### 3. 一套测试口令

建议准备固定测试句子，方便学生验证是否成功：

- 站起来
- 坐下
- 向前走两步
- 向左转一下
- 站起来，然后向前走一步
- 站起来，向右转，再坐下

### 4. 一段演示视频或动图

如果有演示视频，学生更容易理解自己最后要做出什么效果，也更愿意继续做下去。

## 七、建议实现顺序

如果你准备先自己打样，再把过程整理成教程，建议按下面顺序推进。

1. 先确认机器狗 SDK 已经可以稳定控制基础动作
2. 再写最小 Python CLI 调用 AI
3. 再约束 AI 输出固定 JSON
4. 再写动作映射层
5. 最后把整条链路串起来

这个顺序的原因是：

- 硬件链路通常最容易卡
- 先把最不稳定的部分确认掉，后面文档才容易写稳
- 教程可以天然拆成若干独立章节
