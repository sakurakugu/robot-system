# 第 4 章 用 Python 控制机器狗

## 本章目标

这一章先不接 AI，只做一件事：

`让 Python 直接控制机器狗完成一个固定动作序列`

## 为什么要先单独做这一步

因为真实硬件通常比软件更容易出问题。

如果机器狗连不上、SDK 没初始化好、网络没配对，即使 AI 再聪明也没有用。

所以这一章的核心思路是：

- 先确认机器狗本身能被 Python 控制
- 把 AI 这一层完全拿掉

## 本章完成效果

运行：

```bash
python 02_dog_demo.py
```

机器狗完成一个固定演示，例如：

1. 站起来
2. 向前移动一小段
3. 左转
4. 坐下

## 和仓库现有代码的关系

当前仓库里已经有机器狗 SDK 封装和动作执行逻辑，主要位置在：

- `app/robot-onboard/robot-agent/src/core/dog/sdk.py`
- `app/robot-onboard/robot-agent/src/modules/actions/executor.py`

这意味着教程不需要从零造一套 SDK，只需要用更适合教学的方式包一层最小例子。

## 教学上建议暴露的基础动作

为了让学生更容易理解，教程层建议只讲这些动作名：

- `stand`
- `sit`
- `forward`
- `backward`
- `turn_left`
- `turn_right`

但在真正执行时，可以映射到仓库当前内部动作名：

- `stand` -> `stand_up`
- `sit` -> `sit_down`

## 本章建议做法

### 方案 A：直接调用 SDK

适合你准备专门讲一点底层控制时使用。

特点：

- 更接近 SDK 原理
- 代码更像真正控制机器人

### 方案 B：先调用项目里已有动作封装

适合给学生做快速上手版。

特点：

- 更容易跑通
- 更贴近当前仓库已有能力

对于这套教程，我建议优先用“先跑通”的思路，所以可以先做一个轻量包装。

## 安全提醒

在执行任何真实动作前，必须提醒学生：

1. 周围留出空地
2. 确认机器狗电量正常
3. 确认网络连接正常
4. 第一次动作尽量短、慢、少
5. 身边最好有老师或家长在场

## 推荐的最小动作演示

第一版不要做太多动作，建议固定演示：

1. 站起来
2. 前进 1 次
3. 左转 1 次
4. 坐下

## 验收标准

只要学生能稳定完成下面两点，就算本章成功：

1. 能运行脚本且不报连接错误
2. 机器狗能按顺序完成动作

## 进阶说明

当前仓库里的教学示例已经预留了两种模式：

- `dry_run`：只打印动作
- `project_executor`：复用仓库现有 `robot-agent` 动作执行器

这意味着后续你要从“课堂演示版”切到“项目实际执行版”时，不需要推翻教程结构，只需要切换控制器模式。
