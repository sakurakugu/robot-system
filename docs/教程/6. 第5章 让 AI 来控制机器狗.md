# 第 5 章 让 AI 来控制机器狗

## 本章目标

这一章把前面两条链路连起来：

- 一条链路是“Python 调 AI”
- 另一条链路是“Python 控机器狗”

最后形成完整闭环：

`一句中文命令 -> AI 输出动作 -> Python 执行动作 -> 机器狗响应`

## 本章完成效果

运行：

```bash
python 03_ai_control_dog.py
```

输入：

```text
让小狗站起来，然后向前走两步，再坐下
```

程序流程：

1. 把中文发送给 AI
2. AI 返回 JSON
3. Python 解析 JSON
4. Python 逐条执行动作
5. 机器狗完成对应动作

## 这一章真正要解决的问题

核心不是“怎么调用 AI”，也不是“怎么连接机器狗”，而是：

`怎么把 AI 给出的动作名称，安全地映射成真实控制代码`

## 推荐动作数据格式

建议继续使用统一结构：

```json
{
  "actions": [
    {"action": "stand"},
    {"action": "forward", "steps": 2},
    {"action": "sit"}
  ]
}
```

## 为什么一定要做动作映射表

不要直接把 AI 返回的字符串当成 Python 代码执行。

正确做法是建立一个白名单映射表，例如：

```python
{
    "stand": stand,
    "sit": sit,
    "forward": forward,
    "backward": backward,
    "turn_left": turn_left,
    "turn_right": turn_right,
}
```

这样做更安全，也更容易讲清楚。

## 建议执行流程

### 第一步：拿到 AI 输出

先把 AI 返回内容打印出来。

### 第二步：检查 JSON 是否合法

如果不是合法 JSON，就停止执行，并提示错误。

### 第三步：检查动作是否在白名单里

如果动作不在白名单里，就不要执行。

### 第四步：逐条执行

按顺序遍历 `actions` 数组，依次执行。

## 典型伪代码

```python
result = 调用AI(用户输入)
actions = result["actions"]

for item in actions:
    action_name = item["action"]
    执行动作(action_name, item)
```

## 建议加入的保护逻辑

为了提高成功率，建议第一版就加上这些简单保护：

1. 未知动作直接报错
2. `steps` 缺失时使用默认值
3. `steps` 和 `angle` 超过范围时做截断
4. 执行前把动作列表打印出来

## 建议打印日志

初学者很需要看见程序正在做什么，所以建议每一步都打印：

```text
收到用户输入: 让小狗站起来，然后向前走两步
AI 返回: {"actions":[...]}
准备执行动作: stand
准备执行动作: forward
准备执行动作: sit
执行完成
```

## 和仓库当前动作名的映射建议

教程层可以继续使用简单动作名：

- `stand`
- `sit`
- `forward`
- `backward`
- `turn_left`
- `turn_right`

如果接入当前仓库现有动作体系，可以再转成内部动作：

- `stand` -> `stand_up`
- `sit` -> `sit_down`

这样学生看到的是简单名字，项目内部仍然能复用现有逻辑。

## 从教学版切到项目版

当前示例默认使用 `dry_run`，也就是只打印动作。

如果环境已经准备好，可以通过设置环境变量切换到：

- `DOG_CONTROL_MODE=project_executor`

这样教学代码会把动作转发给仓库当前的 `robot-agent` 动作执行子进程。
