# 第 2 章 先用扣子做一个机器狗助手

## 本章目标

这一章先不写 Python，先让学生建立一个直觉：

`AI 不只是聊天，还能把一句中文命令变成程序可以读取的数据`

## 本章完成效果

学生在扣子里输入：

```text
让机器狗站起来，然后向前走两步
```

机器人返回：

```json
{
  "actions": [
    {"action": "stand"},
    {"action": "forward", "steps": 2}
  ]
}
```

## 为什么先用扣子

因为扣子更适合先快速体验结果。

这样做有两个好处：

- 学生先看到 AI 的能力，不会一开始被代码吓住
- 后面写 Python 时，学生会知道自己要实现什么效果

## 这一步我们要做什么

我们要在扣子里做一个很简单的“机器狗指令翻译器”。

它只做一件事：

- 把中文命令翻译成固定 JSON

它不负责真正控制机器狗。

## 建议的智能体设定

你可以给扣子里的机器人一个非常明确的任务描述，例如：

```text
你是一个机器狗动作翻译助手。

你的任务是把用户输入的中文命令，转换成固定格式的 JSON。

你只能使用以下动作：
- stand
- sit
- forward
- backward
- turn_left
- turn_right

要求：
1. 只输出 JSON，不输出解释
2. 如果一句话里有多个动作，输出 actions 数组
3. 如果是前进或后退，可以使用 steps 参数
4. 如果是转向，可以使用 angle 参数
5. 如果用户的命令不明确，尽量转换成最接近的基础动作
```

## 推荐动作格式

建议统一使用下面这个格式：

```json
{
  "actions": [
    {"action": "stand"},
    {"action": "forward", "steps": 2}
  ]
}
```

推荐原因：

- 以后 Python 容易解析
- 一条命令和多条命令能统一处理
- 后面连接机器狗时更顺手

## 测试口令

建议学生至少测试下面几句：

```text
站起来
坐下
向前走两步
向后退一步
向左转一下
站起来，然后向右转，再坐下
```

## 观察重点

学生在测试时，要重点观察这几件事：

1. AI 有没有输出多余文字
2. 动作名称有没有跑偏
3. 多动作命令有没有保持顺序
4. 参数有没有合理填进去

## 常见问题

### 1. AI 输出了一大段解释

解决方法：

- 把提示词里的“只输出 JSON，不输出解释”写得更明确
- 在示例中直接给出标准输出格式

### 2. AI 自己发明了新动作

解决方法：

- 在提示词里明确写“只能使用给定动作”
- 给出白名单动作列表

### 3. 同一句话每次输出格式不一样

解决方法：

- 减少提示词中的自由描述
- 多放几个输入输出示例
- 尽量统一格式，只保留一个 JSON 模板

## 本章小结

这一章的重点不是“做出一个很聪明的机器人”，而是让学生看到：

- 自然语言可以转成结构化数据
- 结构化数据才能方便程序处理

后面写 Python 时，做的事情其实就是把这个过程自动化。

## 本章练习

请学生自己补充 3 条机器狗命令，并观察输出是否符合要求。

如果输出不稳定，就继续修改提示词，直到格式稳定为止。
