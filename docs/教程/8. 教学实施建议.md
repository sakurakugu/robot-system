# 教学实施建议

## 适合的教学节奏

如果对象是已经有 Python 基础的中小学生，建议不要一开始上满太多概念。

比较适合的节奏是：

1. 先看效果
2. 再拆流程
3. 再写最小代码
4. 最后做自由改造

## 建议课时安排

### 方案 A：4 课时速通版

1. 第 1 课时：项目介绍 + 扣子体验
2. 第 2 课时：Python CLI 调 AI
3. 第 3 课时：机器狗固定动作演示
4. 第 4 课时：AI 控制机器狗 + 小项目展示

### 方案 B：6 课时稳妥版

1. 第 1 课时：项目目标和流程理解
2. 第 2 课时：扣子智能体体验
3. 第 3 课时：Python 调 AI
4. 第 4 课时：JSON 和动作映射
5. 第 5 课时：控制机器狗
6. 第 6 课时：整合与作品展示

## 教学重点

在这套课里，建议重点反复强调三件事：

1. 输入和输出
2. 结构化数据
3. 分层调试

### 输入和输出

学生最容易真正学会的，不是某个库的细节，而是：

- 用户输入了什么
- 程序输出了什么
- 两者之间经过了怎样的转换

### 结构化数据

一定要让学生明白：

- 自然语言适合人看
- JSON 更适合程序处理

### 分层调试

让学生知道出问题时可以这样查：

1. AI 输出对不对
2. JSON 格式对不对
3. Python 解析对不对
4. 机器狗执行链路对不对

## 常见卡点

### 1. 学生觉得 JSON 很抽象

解决方法：

- 多举动作列表示例
- 把 JSON 理解成“动作清单”

### 2. 学生分不清 AI 和 Python 各自做什么

解决方法：

- 每次都用一句话重复：
  AI 负责理解，Python 负责执行

### 3. 一接硬件就紧张

解决方法：

- 先做打印版
- 再做模拟版
- 最后再做真实执行版

## 建议的课堂顺序

每次上课尽量保持这个顺序：

1. 先演示效果
2. 再解释今天只做哪一小步
3. 再让学生动手
4. 最后统一排错

这样会比先讲大量概念更有效。
