# 子仓库与拉取说明

## 当前结构

当前父仓库为 `robot-system`，4 个子仓库以 submodule 形式挂载在：

- `repos/robot-cloud`
- `repos/robot-onboard`
- `repos/robot-phone`
- `repos/robot-pc`

当前 `.gitmodules` 中使用的是 GitHub 远端地址：

- `git@github.com:sakurakugu/robot-cloud.git`
- `git@github.com:sakurakugu/robot-onboard.git`
- `git@github.com:sakurakugu/robot-phone.git`
- `git@github.com:sakurakugu/robot-pc.git`

这种方式适合直接在任意新机器上递归拉取整个父仓库。

## 首次克隆

推荐直接递归拉取：

```bash
git clone --recurse-submodules <robot-system 仓库地址>
cd robot-system
```

如果父仓库已经拉下来，但子模块目录还是空的：

```bash
git submodule update --init --recursive
```

## 日常使用

### 方案一：按父仓库锁定的版本同步

这种方式最稳，父仓库记录到哪个子模块提交，你本地就切到哪个提交：

```bash
git pull
git submodule update --init --recursive
```

适合：

- 复现某个确定版本
- 切回某次历史状态
- 保证父仓库和 4 个子仓库版本完全对应

### 方案二：直接把子仓库更新到最新

如果你想直接拉子仓库自己的最新提交：

```bash
git submodule update --remote --merge
```

这会把每个子模块更新到它当前跟踪分支的最新提交，并把父仓库里的 gitlink 一起改掉。

更新后建议检查：

```bash
git status
```

如果确认没问题，再在父仓库提交一次，用来记录新的子模块指针。

## 单独更新某一个子仓库

例如只更新云端：

```bash
git -C repos/robot-cloud pull
git status
```

如果你要让父仓库记录这次更新，再在父仓库提交一次即可。

## 查看子模块状态

```bash
git submodule status
```

如果某个子模块前面有：

- `-`：还没初始化
- `+`：子模块当前提交和父仓库记录的不一致

## 新机器迁移

当前 `.gitmodules` 已经使用远端地址，直接递归克隆即可。

目录示例：

```text
Repos/
  robot-system/
```

## 改成远端地址

如果后面你要切换子模块地址，例如切到 SSH、HTTPS、内网 Git 服务，可以这样改：

```bash
git submodule set-url repos/robot-cloud <robot-cloud 远端地址>
git submodule set-url repos/robot-onboard <robot-onboard 远端地址>
git submodule set-url repos/robot-phone <robot-phone 远端地址>
git submodule set-url repos/robot-pc <robot-pc 远端地址>
```

然后同步本地配置：

```bash
git submodule sync --recursive
```

## 常见问题

### 子模块目录是空的

执行：

```bash
git submodule update --init --recursive
```

### 父仓库 pull 之后，子模块还是旧版本

执行：

```bash
git submodule update --init --recursive
```

因为父仓库只更新了 gitlink，子模块工作目录不会自动切换。

### 我只想进某个子仓库开发

直接进入对应目录即可：

```bash
cd repos/robot-pc
```

子模块本身就是完整 git 仓库，可以正常 `git status`、`git log`、`git checkout`、`git pull`。
