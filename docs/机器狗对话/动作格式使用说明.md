# 动作格式使用说明

## 概述

前端现在支持通过特殊格式 `{{action=xxx}}` 直接发送动作指令到机器狗，无需通过 AI 对话。

## 使用格式

### 基本格式

```
{{action=动作名称}}
```

示例：
- `{{action=stand_up}}` - 站起来
- `{{action=sit_down}}` - 坐下
- `{{action=shake_hand}}` - 握手
- `{{action=wave}}` - 挥手
- `{{action=dance}}` - 跳舞

### 带参数的格式

```
{{action=动作名称,参数名1=值1,参数名2=值2}}
```

示例：
- `{{action=walk_forward,steps=3}}` - 向前走3步
- `{{action=turn_left,angle=90}}` - 向左转90度
- `{{action=dance,type=waltz,speed=1.5}}` - 跳华尔兹舞，速度1.5倍
- `{{action=shake_hand,hand=left}}` - 用左手握手

## 支持的动作

根据 `action-controller.ts` 中定义的动作白名单，当前支持以下动作：

- `stand_up` - 站起来
- `sit_down` - 坐下
- `turn_left` - 向左转（可带 `angle` 参数，最大720度）
- `turn_right` - 向右转（可带 `angle` 参数，最大720度）
- `shake_hand` - 握手
- `wave` - 挥手
- `nod` - 点头
- `dance` - 跳舞
- `walk_forward` - 向前走（可带 `steps` 参数，最大3步）
- `walk_backward` - 向后走（可带 `steps` 参数，最大3步）

## 参数说明

### 数字参数

- 如果参数值是数字，会自动转换为数字类型
- 例如：`steps=3` → `{ steps: 3 }`
- 例如：`speed=1.5` → `{ speed: 1.5 }`

### 字符串参数

- 如果参数值不是数字，保留为字符串
- 例如：`hand=left` → `{ hand: "left" }`
- 例如：`type=waltz` → `{ type: "waltz" }`

## 使用方法

1. 在聊天输入框中输入动作格式（必须是精确格式）
2. 点击"发送给机器狗"或"发送给大模型"按钮（两者都会检测动作格式）
3. 或使用快捷键：
   - `Shift + Enter`：发送给机器狗
   - `Ctrl + Enter`：发送给大模型

## 格式规则

**必须遵守以下规则，否则不会被识别为动作格式：**

1. **精确格式**：必须完全匹配 `{{action=xxx}}` 格式，前后不能有其他文字
2. **动作名称**：只能包含字母、数字和下划线，且必须以字母或下划线开头
3. **参数格式**：参数必须是 `key=value` 格式，多个参数用逗号分隔
4. **无空格**：格式中不应包含额外的空格

### 有效示例

✅ `{{action=stand_up}}`
✅ `{{action=walk_forward,steps=3}}`
✅ `{{action=turn_left,angle=90}}`
✅ `{{action=dance,type=waltz,speed=1.5}}`

### 无效示例

❌ `hello {{action=stand_up}}` - 前面有其他文字
❌ `{{action=stand_up}} hello` - 后面有其他文字
❌ `{{ action=stand_up }}` - 包含额外空格
❌ `{{action=stand-up}}` - 动作名称包含连字符
❌ `{{action=123}}` - 动作名称以数字开头

## 技术实现

### 前端 (ChatView.vue)

- 在 `sendMessage` 函数中添加了 `parseActionFormat` 函数
- 发送前检测输入文本是否匹配动作格式
- 如果匹配，通过 WebSocket 发送 `action_input` 消息

### 后端 (websocket/index.ts)

- 添加了 `action_input` 消息类型处理
- 在 `handleActionInput` 方法中验证并转发动作到机器狗
- 记录动作日志到数据库

### 客户端 (robot_client.py)

- 添加了 `_parse_action_format` 方法解析动作格式
- 在 `_handle_text_response` 中检测文本是否包含动作格式
- 如果检测到动作格式，直接调用 `action_executor` 执行动作
- 支持从前端、后端或直接发送的动作格式

### 类型定义 (types/index.ts)

- 添加了 `ActionInputMessage` 接口
- 更新了 `ClientMessage` 联合类型

## 注意事项

1. 动作必须在白名单中才能执行（安全限制）
2. 某些动作有参数范围限制（例如 `walk_forward` 最多3步）
3. 动作执行有频率限制（默认每分钟最多10次）
4. 发送动作不会触发 TTS 语音输出
5. **客户端会自动解析文本响应中的动作格式并直接执行**，无需额外配置

## 示例场景

### 场景1：快速控制

用户想让机器狗站起来，直接输入：
```
{{action=stand_up}}
```

### 场景2：精确移动

用户想让机器狗向前走3步：
```
{{action=walk_forward,steps=3}}
```

### 场景3：转向控制

用户想让机器狗向左转90度：
```
{{action=turn_left,angle=90}}
```

### 场景4：复杂动作

用户想让机器狗跳一段特定的舞蹈：
```
{{action=dance,type=waltz,speed=1.5}}
```

### 场景5：客户端直接接收

当后端或UI发送包含动作格式的文本响应时，客户端会自动检测并执行：
- 后端发送：`text_response` 消息内容为 `{{action=stand_up}}`
- 客户端接收后自动解析并执行站立动作
- 无需通过 `action_command` 消息类型

## 常见问题

**Q: 为什么我的动作格式没有被识别？**
A: 请确保格式完全匹配，前后不能有其他文字，动作名称必须符合命名规则。

**Q: 我可以自定义动作吗？**
A: 需要在后端 `action-controller.ts` 的 `ALLOWED_ACTIONS` 白名单中添加。

**Q: 参数范围限制在哪里配置？**
A: 在 `action-controller.ts` 的 `SAFETY_RULES` 中配置。

**Q: 如何查看动作执行日志？**
A: 动作执行会自动记录到数据库的 action_logs 表中。
