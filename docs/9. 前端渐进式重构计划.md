# 9. 前端渐进式重构计划

## 结论

当前前端需要重构，但不建议整体重写。

- 云端前端已经进入“需要结构性重构”的阶段。
- 手机端整体还能继续迭代，但核心大页面已经需要拆分。
- 适合采用“边开发边收口”的渐进式重构，不适合停下来推翻重做。

## 范围

- `app/cloud-server/前端`
- `app/phone-app/RobotPhone`

## 当前判断依据

### 云端前端

1. 已经有模块化雏形，但边界没有真正收口。

- 例如 `src/modules/robot/store.ts` 和 `src/modules/robot/api.ts` 已存在。
- 但 `src/modules/robot/views/RobotManage.vue` 仍然直接 `fetch`、定义临时类型、做数据清洗、自己维护更新状态。

2. 页面职责过重。

- `src/modules/role/views/RoleManage.vue` 同时承担表格展示、弹窗表单、接口请求、机器人解绑、模型配置联动等职责。
- `loadRoles` 中还存在按角色逐个请求绑定机器人数量的 N+1 问题。

3. 大文件已经影响维护。

- `src/modules/choreo/components/timeline/TimelineEditor.vue` 约 1500 行。
- `src/modules/choreo/views/ChoreoEditor.vue` 约 1200 行。
- `src/modules/robot/views/RobotSettings.vue` 约 1100 行。
- `src/modules/role/views/RoleManage.vue` 约 600 行。

4. 工程规范问题已经暴露过一轮，说明项目需要持续收口。

- `npm run lint` 和 `npm run typecheck` 当前都可通过。
- 但此前已经出现过裸 `fetch`、空 `catch`、弱类型对象拼装、大页面混合多职责等问题。
- 说明工程基线虽然恢复了，但结构性维护成本仍然偏高，继续重构仍然必要。

### 手机端

1. 基础分层比云端更健康。

- 已有 `shared/net/http.ts`。
- `features/robots/api.ts` 已经承担了机器人数据读写与本地缓存同步。

2. 核心页面明显过重。

- `src/features/robots/screens/机器人操作屏幕.tsx` 约 1080 行。
- `src/features/robots/components/RobotChatPanel.tsx` 约 1110 行。
- 单文件同时处理导航、手势、多点触控、视频、拍照、音频、弹幕、状态展示，维护成本很高。

3. 类型边界还比较松。

- 多处存在 `useNavigation<any>`、`useRoute<any>`、`Record<string, any>`、`catch (e: any)`。
- 这些问题暂时不会马上阻塞功能，但会持续放大后续改动成本。

## 不做的事

- 不做整站重写。
- 不为了“看起来更现代”去大规模重做 UI。
- 不在没有稳定边界前，先抽一堆空泛的通用组件。
- 不一次性追求所有 `any` 清零。

## 重构原则

1. 先收口数据边界，再拆页面。
2. 先抽业务逻辑，再抽纯展示组件。
3. 每次只动一个功能域，保证热更新后能马上验证。
4. 优先消除页面里的直接 `fetch`、重复数据转换、重复错误处理。
5. 每完成一个阶段，都要跑对应项目的 `lint` 和 `typecheck`。

## 优先级

### P0：先把云端前端拉回可持续状态

目标：

- 让 `lint` 恢复可用。
- 统一视图层的数据获取方式。
- 建立后续拆分时可以复用的最小边界。

先做这些：

- 修复 `app/cloud-server/前端` 当前 `lint` 报错。
- 明确约定：`view` 层不再直接写裸 `fetch`，优先走模块 `api` 或 `store`。
- 清理明显无意义的空 `catch`、无用变量、规则配置错误。

### P1：先重构云端机器人模块

原因：

- 功能核心。
- 访问频率高。
- 已经有 `api/store` 雏形，最容易先收口成功。

拆分目标：

- `RobotManage.vue` 只保留页面展示和交互编排。
- 列表加载、数据清洗、更新、删除、推送固件移到 `store` 或 `composables`。
- 机器人接口返回值格式统一，不再在页面里临时解析 `metadata`。

建议顺序：

1. 收口 `RobotManage.vue`
2. 收口 `RobotSettings.vue`
3. 收口 `RobotOperation.vue`

当前进展（2026-03-30）：

- `app/cloud-server/前端/src` 范围内已清理裸 `fetch`，请求入口已统一收口到 `api/http` 或 composable。
- 已完成 `RobotManage.vue` 收口，列表加载、删除、固件推送已统一走 `robot store/api`。
- 已完成 `RobotAdd.vue`、`RobotOperation.vue`、`RobotOperationEdit.vue` 页面级 `fetch` 清理，机器人模块页面层已不再直接请求机器人接口。
- 已完成 `RobotSettings.vue` 第一阶段收口，页面级 `fetch` 已移除，并抽出 `settings.ts`、`normalize.ts` 承担详情映射、自动保存组包与共享归一化。
- 已完成 `RobotSettings.vue` 的网络、日志、AI 配置子块拆分，页面主文件继续缩小。
- 已完成 `RobotSettings.vue` 的基本信息、系统升级子块拆分，主文件目前主要承担状态编排与跨区逻辑。
- 已完成 `RobotSettings.vue` 的音量控制、详情加载/保存/解绑逻辑下沉到 composable，主文件已经收敛为薄编排层。
- 已完成 `RobotSettings.vue` 最后一轮瘦身，页面当前只保留页头、tab 编排与状态接线。
- `RobotSettings.vue` 后续可继续考虑把日志 mock 和升级 mock 再下沉到 service，或直接接真实后端能力。

### P2：重构云端角色与设置模块

重点问题：

- `RoleManage.vue` 职责混杂。
- 角色列表存在 N+1 请求。
- 多处配置页面仍保留页面级请求与弱类型对象拼装。

拆分目标：

- 提取角色管理的 `api`、`types`、`useRoleManage`。
- 将“角色表单”和“绑定机器人列表”拆成独立组件。
- 把机器人数量改成后端聚合字段，或前端并发聚合后统一组装，避免页面内串行请求。

当前进展（2026-03-30）：

- `RoleManage.vue` 已完成第一阶段收口。
- `role/api.ts` 已统一切到项目 `http` 请求封装，不再保留模块内裸 `fetch`。
- `ParamsManage.vue`、`ChatView.vue`、`choreo/api.ts` 与 `useWebSocket.ts` 的裸 `fetch` 已清理。
- `settings/types.ts` 已对齐后端实际返回的 LLM 配置结构，前端已改为 `provider + providers` 视图模型，并支持按供应商嵌套组包更新。
- `ParamsManage.vue` 已完成第一阶段逻辑下沉，密钥掩码、编辑态切换、更新 payload 组装已抽到 `src/modules/settings/params.ts`。
- `ParamsManage.vue` 已完成第二阶段模板收口，重复密钥输入块已抽成 `src/modules/settings/components/MaskedSecretInput.vue`，页面主文件进一步回到展示编排层。
- `ChatView.vue` 已完成第一阶段瘦身，历史消息转换、动作文本解析、目标框样式与音频 URL 转换已抽到 `src/modules/conversation/chat.ts`。
- `ChatView.vue` 已继续拆出 `src/modules/conversation/composables/useChatAudio.ts`，TTS 请求、音频分配、播放与 blob URL 清理不再堆在页面里。
- `useWebSocket.ts` 的 `onMessage` 已补齐取消订阅能力，`ChatView.vue`、`RobotOperation.vue`、`ChoreoEditor.vue` 已在卸载时清理监听，避免重复注册后重复处理消息。

### P3：重构手机端机器人操作与对话

先做：

- `机器人操作屏幕.tsx`
- `RobotChatPanel.tsx`

拆分方向：

- 把控制逻辑拆成 `hooks`：
  - 摇杆输入
  - 顶部工具栏状态
  - 拍照与相册保存
  - 直连控制回调注册
  - 弹幕与提示消息
- 把 UI 拆成组件：
  - 顶部工具栏
  - 浮层操作区
  - 动作按钮区
  - 速度弹窗

注意：

- 手机端这部分交互复杂，先保持行为不变，再做结构调整。
- 不要把多点触控逻辑和视觉层同时大改。

当前进展（2026-03-30）：

- `机器人操作屏幕.tsx` 已拆出屏幕状态 hook、摇杆触摸 hook、顶部工具栏、浮层操作区与速度弹窗，页面主文件回到展示编排层。
- `RobotChatPanel.tsx` 已拆出聊天会话 hook、音频播放 hook、消息气泡与输入区组件，消息历史映射与动作文本解析已收口到独立模块。

### P4：补齐统一规范

目标：

- Web 和手机端都采用一致的边界习惯。

建议统一：

- 页面只负责展示和交互编排。
- 接口请求统一走 `api` 层。
- 数据组装统一放在 `store`、`service` 或 `composable/hook`。
- 页面路由参数补齐明确类型，不再普遍使用 `any`。

## 建议的分批落地顺序

1. 云端前端先修 `lint`，恢复工程基线。
2. 云端机器人模块先收口。
3. 云端角色模块拆分。
4. 手机端 `机器人操作屏幕` 拆逻辑。
5. 手机端 `RobotChatPanel` 拆逻辑。
6. 最后再处理编舞模块的大文件拆分。

## 每阶段验收标准

- 当前阶段页面功能不回退。
- `lint` 和 `typecheck` 至少在当前子项目内通过。
- 页面里的直接 `fetch` 数量减少。
- 新增的 `types`、`api`、`hook/composable` 能被下一个页面继续复用。
- 单文件复杂度持续下降，而不是把复杂度转移到另一个“超级工具文件”。
