# 全端链路流程图

> 流程图可以用 Typora 查看 GUI

本文把当前仓库里的几个主要端统一整理成 Mermaid 流程图，方便快速理解：

- 手机端 `repos/robot-phone`
- 电脑端工作站 `repos/robot-pc`
- 云端 `repos/robot-cloud`
- 机器狗本体 `repos/robot-onboard`

## 1. 总体拓扑

```mermaid
flowchart LR
  subgraph 手机端
    phoneApp[RobotPhone App]
  end

  subgraph 电脑端工作站
    pcWeb[工作站前端<br/>Vue 3]
    pcApi[工作站后端<br/>Node.js + WebSocket]

    pcWeb --> pcApi
    pcApi <--> pcData

  subgraph 云端

    cloudApi[云端后端<br/>Node.js + WebSocket]
    cloudDb[(PostgreSQL)]
    cloudAi[LLM / ASR / TTS]
    cloudWeb --> cloudApi
    cloudApi <--> cloudDb
    cloudApi <--> cloudAi
  end

  subgraph 机器狗本体
    agent[robot-agent]
    server[robot-server]
    runtime[robot-runtime]
    ros[robot-ros]
    dog[运控 / SDK / 底层控制器]

    agent <--> server
    agent <--> runtime

    ros <--> lidar

  phoneApp -->|默认云端 API / WebSocket| cloudApi
  phoneApp -.->|局域网直控<br/>ws://robotIp:8082| agent
  phoneApp -.->|局域网直读遥测<br/>http://robotIp:8080| server
  phoneApp -.->|局域网直连视频<br/>http://robotIp:8889/test/whep| video

  pcApi -->|局域网 HTTP| server
  pcApi -->|工作站业务 WebSocket| agent

  cloudApi -->|云端业务 WebSocket| agent
```

## 2. 电脑端工作站链路

当前电脑端是本地优先、局域网直连的工作站模式。

```mermaid
flowchart LR
  user[操作人员] --> browser[浏览器]
  browser --> pcWeb[工作站前端]
  pcWeb -->|HTTP| pcApi[工作站后端]

  pcApi -->|扫描本地地图目录| mapDir[本地 yaml / pgm / png 地图]
  pcApi -->|GET /api/v1/telemetry/full| robotServer[robot-server]
  robotAgent[robot-agent] -->|业务 WebSocket 反向接入工作站| pcApi
  pcApi -->|map_command / control / choreo| robotAgent

  robotAgent -->|调用本地运行时客户端| runtime[robot-runtime]
  runtime -->|启动 / 停止建图、定位、导航| ros[robot-ros]
  ros --> slam[slam_toolbox / nav2]
  ros --> lidar[激光雷达 /scan]

  pcApi -->|返回运行状态、位姿、地图列表| pcWeb
```

### 说明

- 当前电脑端地图工作台主要是“静态地图底图 + 位姿/状态”模式。
- 当前地图工作台默认通过工作站后端读 `robot-server`，并通过工作站业务 WebSocket 与 `robot-agent` 收发命令。
- 当前仓库里已经具备雷达、建图、定位链路，但电脑端地图页还没有把实时 `scan` 或实时栅格图直接推到前端画布。

## 3. 云端链路

云端负责远程接入、账号权限、资产管理，以及 AI 能力接入。

```mermaid
flowchart LR
  remoteUser[远程用户] --> cloudWeb[云端前端]
  cloudWeb -->|HTTP / WebSocket| cloudApi[云端后端]

  cloudApi <--> db[(PostgreSQL)]
  cloudApi <--> ai[LLM / ASR / TTS]
  cloudApi <--> agent[robot-agent]

  agent -->|本地 HTTP| server[robot-server]
  agent -->|本地运行时命令| runtime[robot-runtime]
  runtime --> ros[robot-ros]
```

### 说明

- 云端是远程管理中枢，不适合直接承载原始激光雷达数据流。
- 适合放在云端的是账号、角色、编舞项目、机器人资产、远程任务、AI 对话与音频能力。
- 本体的建图、定位、导航、雷达驱动仍应留在本地完成。

## 4. 手机端链路

手机端当前是“云端优先 + 局域网直连能力并存”的模式。

```mermaid
flowchart TD
  phone[手机 App]

  subgraph 云端路径
    phone -->|环境 baseUrl /api/v1| cloudApi[云端后端]
    phone -->|手机独立 WebSocket| cloudWs[云端业务通道]
  end

  subgraph 局域网直连路径
    phone -.->|ws://robotIp:8082| directWs[robot-agent 直控 WS]
    phone -.->|http://robotIp:8080/api/v1/telemetry| telemetry[robot-server 遥测]
    phone -.->|http://robotIp:8889/test/whep| whep[本地视频流]
    phone -.->|mDNS / SSH / 安装包| localTools[发现与运维能力]
  end
```

### 说明

- 手机端的数据管理、账号、角色、编舞项目更偏向走云端。
- 手机端为了降低操控延迟，也保留了局域网直控链路。
- 视频、遥测、群控这类对时延敏感的能力，天然更适合局域网直连。

## 5. 本体内部链路

本体内部可以分成“接入层、运行时层、ROS 导航层、硬件层”。

```mermaid
flowchart LR
  subgraph 接入层
    agent[robot-agent]
    server[robot-server]
  end

  subgraph 运行时层
    runtime[robot-runtime]
  end

  subgraph ROS 导航层
    ros[robot-ros]
    slam[建图 / 定位 / 导航]
  end

  subgraph 硬件层
    dog[运控 / SDK]
    lidar[2D 激光雷达]
    camera[相机]
    audio[音频设备]
  end

  dog -->|UDP 遥测| server
  agent -->|HTTP 配置 / 遥测读取| server
  agent -->|导航 / 地图 / 巡逻命令| runtime
  runtime -->|启动 ROS2 组件| ros
  ros --> slam
  lidar --> ros
  camera --> agent
  audio --> agent

  agent -->|运行时摘要 / 状态广播| out[云端或工作站]
```

### 分层职责

- `robot-server`：本地 HTTP 服务，负责配置、遥测查询、部分运维接口。
- `robot-agent`：对外通信总入口，负责接云端、接工作站、接手机直控，以及把命令转给本体内部。
- `robot-runtime`：统一导航、地图、任务、状态聚合。
- `robot-ros`：承接雷达驱动、建图、定位、导航等 ROS2 能力。
