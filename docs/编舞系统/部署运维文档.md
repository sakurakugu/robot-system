## 1. 环境要求

### 1.1 操作系统

- **Windows**: Windows 10/11 (64位)
- **macOS**: macOS 11+ (Big Sur 或更高版本)
- **Linux**: Ubuntu 20.04+, Debian 11+, 或其他现代发行版

### 1.2 软件依赖

#### 必需组件

| 软件 | 版本要求 | 说明 |
|------|----------|------|
| Node.js | 20.x 或更高 | JavaScript 运行时 |
| npm | 10.x 或更高 | Node.js 包管理器 |
| Python | 3.10 或更高 | Python 运行时 |

#### Python 依赖

```bash
# 核心依赖
paramiko>=3.0.0        # SSH 连接
sshpass                # SSH 密码认证（Linux）
```

### 1.3 硬件要求

| 项目 | 最低配置 | 推荐配置 |
|------|----------|----------|
| CPU | 双核 2GHz | 四核 3GHz |
| 内存 | 4GB | 8GB 或更高 |
| 硬盘 | 10GB 可用空间 | 20GB 或更高 |
| 网络 | 100Mbps | 1Gbps |

## 2. 安装部署

### 2.1 克隆项目

```bash
git clone <repository-url> robot-dog
cd robot-dog
```

### 2.2 安装依赖

#### 自动安装（推荐）

使用一键启动脚本会自动检查并安装依赖：

```bash
chmod +x start.sh
./start.sh
```

#### 手动安装

**后端依赖**:

```bash
cd app/backend
npm install
npm run build
cd ../..
```

**前端依赖**:

```bash
cd app/frontend
npm install
cd ../..
```

**Python 依赖**:

```bash
pip3 install paramiko
# Linux 用户还需安装 sshpass
# sudo apt-get install sshpass  # Ubuntu/Debian
# sudo yum install sshpass       # CentOS/RHEL
```

### 2.3 初始化数据库

```bash
cd app/backend
npm run init-db
cd ../..
```

**输出示例**:

```
初始化数据库中...
数据目录: /home/user/.local/share/RobotDogControl
主数据库: /home/user/.local/share/RobotDogControl/main.db
工程目录: /home/user/Documents/RobotDogControlProjects
正在创建不存在的目录...
创建目录: /home/user/.local/share/RobotDogControl
创建目录: /home/user/Documents/RobotDogControlProjects
主数据库初始化成功！
用户: [ { uuid: '00000000-0000-0000-0000-000000000000', username: 'default' } ]
工程: []

数据库初始化完成！
```

### 2.4 安装 SDK 库文件

SDK 的 `.so` 库文件（共享库）需要单独获取：

```bash
# 克隆库文件仓库到临时目录
git clone <so-repository-url> /tmp/so_repo

# 复制到目标目录
mkdir -p app/robot-control/lib/so/x86_64
mkdir -p app/robot-control/lib/so/aarch64
cp /tmp/so_repo/x86_64/*.so app/robot-control/lib/so/x86_64/
cp /tmp/so_repo/aarch64/*.so app/robot-control/lib/so/aarch64/

# 清理临时文件
rm -rf /tmp/so_repo
```

**注意**: 确保库文件与你的系统架构匹配。

## 3. 启动与停止

### 3.1 一键启动

使用提供的启动脚本：

```bash
./start.sh
```

**脚本功能**:

1. 检查环境（Node.js、Python）
2. 安装缺失的依赖
3. 初始化数据库
4. 启动后端服务（端口 3000）
5. 启动前端服务（端口 5173）
6. 显示访问地址和日志路径

**启动成功输出**:

```
========================================
  ✅ 系统启动成功！
========================================

  前端界面: http://localhost:5173
  后端API:  http://localhost:3000
  WebSocket: ws://localhost:3000
  健康检查: http://localhost:3000/health

  后端日志: logs/backend.log
  前端日志: logs/frontend.log

  后端进程 PID: 12345
  前端进程 PID: 12346

  按 Ctrl+C 停止所有服务
========================================
```

### 3.2 停止服务

**方式1: 使用 Ctrl+C**

在启动脚本的终端按 `Ctrl+C` 停止所有服务。

**方式2: 使用停止选项**

```bash
./start.sh --stop
# 或
./start.sh -x
```

**方式3: 手动停止**

```bash
# 读取 PID 并停止进程
kill $(cat logs/backend.pid)
kill $(cat logs/frontend.pid)

# 清理 PID 文件
rm -f logs/backend.pid logs/frontend.pid
```

### 3.3 重启服务

```bash
./start.sh --restart
# 或
./start.sh -r
```

### 3.4 仅启动（不重启）

```bash
./start.sh --start
# 或
./start.sh -s
```

### 3.5 开发模式

**后端开发模式**（带热重载）:

```bash
cd app/backend
npm run dev
```

**前端开发模式**（带热重载）:

```bash
cd app/frontend
npm run dev
```

### 3.6 生产模式

**构建前端**:

```bash
cd app/frontend
npm run build
# 输出到 dist/ 目录
```

**启动后端**（生产模式）:

```bash
cd app/backend
npm run build
npm start
```

## 4. 配置说明

### 4.1 后端配置

**文件**: `app/backend/src/config/index.ts`

**主要配置项**:

```typescript
export const CONFIG = {
  APP_NAME: 'RobotDogControl',
  APP_VERSION: '0.1.0',
  DATA_DIR: process.env.DATA_DIR || getDataDir(),
  PROJECTS_DIR: process.env.PROJECTS_DIR || getProjectsDir(),
  TEMP_DIR: path.join(os.tmpdir(), 'RobotDogControl'),
  
  SERVER: {
    PORT: parseInt(process.env.PORT || '3000', 10),
    HOST: process.env.HOST || '0.0.0.0',
  },
  
  WEBSOCKET: {
    PORT: parseInt(process.env.WS_PORT || '3001', 10),
  },
  
  PYTHON: {
    SCRIPT_DIR: path.join(process.cwd(), '..', 'robot-control'),
    PYTHON_CMD: process.env.PYTHON_CMD || 'python3',
  },
};
```

**环境变量**:

| 变量名 | 默认值 | 说明 |
|--------|--------|------|
| `PORT` | 3000 | 后端 HTTP 服务端口 |
| `HOST` | 0.0.0.0 | 后端监听地址 |
| `WS_PORT` | 3001 | WebSocket 服务端口 |
| `DATA_DIR` | 平台默认 | 数据目录路径 |
| `PROJECTS_DIR` | 平台默认 | 工程目录路径 |
| `PYTHON_CMD` | python3 | Python 命令 |

**自定义环境变量**:

创建 `.env` 文件：

```bash
PORT=3001
WS_PORT=3002
DATA_DIR=/custom/data/path
PROJECTS_DIR=/custom/projects/path
PYTHON_CMD=/usr/bin/python3.11
```

### 4.2 前端配置

**文件**: `app/frontend/vite.config.ts`

**开发服务器配置**:

```typescript
export default defineConfig({
  server: {
    port: 5173,
    host: '0.0.0.0',
    proxy: {
      '/api': {
        target: 'http://localhost:3000',
        changeOrigin: true,
      },
    },
  },
});
```

**环境变量**:

创建 `app/frontend/.env.local`：

```
VITE_API_BASE_URL=http://localhost:3000/api
VITE_WS_URL=ws://localhost:3001
```

## 5. 日志管理

### 5.1 日志文件位置

**开发模式**:

```
项目根目录/
├── logs/
│   ├── backend.log      # 后端日志
│   ├── frontend.log     # 前端日志
│   ├── backend.pid      # 后端进程 PID
│   └── frontend.pid     # 前端进程 PID
```

**生产模式**（建议）:

```
~/.local/share/RobotDogControl/logs/
├── app.log              # 应用日志
├── robot.log            # 机器人控制日志
└── error.log            # 错误日志
```

### 5.2 日志格式

**后端日志格式**:

```
[2026-01-13T10:30:45.123Z] INFO 启动机器人狗控制系统后端...
[2026-01-13T10:30:45.456Z] INFO 数据库已初始化
[2026-01-13T10:30:45.789Z] INFO 服务器运行在 http://localhost:3000
```

**机器人控制日志格式**:

```
[2026-01-13T10:31:00.123456+08:00] [+] [131] standUp() -> 0
[2026-01-13T10:31:05.234567+08:00] [+] [131] move(1.0, 0, 0) -> 0
[2026-01-13T10:31:10.345678+08:00] [-] [131] jump() -> 0x3013
```

**日志级别**:

- `INFO`: 一般信息
- `ERROR`: 错误信息
- `[+]`: 动作执行成功
- `[-]`: 动作执行失败

### 5.3 查看日志

**实时查看**:

```bash
# 后端日志
tail -f logs/backend.log

# 前端日志
tail -f logs/frontend.log

# 同时查看多个日志
tail -f logs/backend.log logs/frontend.log
```

**搜索日志**:

```bash
# 搜索错误
grep ERROR logs/backend.log

# 搜索特定机器人的动作
grep "\[131\]" logs/backend.log

# 搜索失败的动作
grep "\[-\]" logs/backend.log
```

### 5.4 日志轮转

**手动清理旧日志**:

```bash
# 保留最近 7 天的日志
find logs/ -name "*.log" -mtime +7 -delete
```

**使用 logrotate（Linux）**:

创建 `/etc/logrotate.d/robot-dog`：

```
/home/user/.local/share/RobotDogControl/logs/*.log {
    daily
    rotate 7
    compress
    missingok
    notifempty
}
```

## 6. 数据备份

### 6.1 备份策略

#### 主数据库备份

```bash
# 创建备份目录
mkdir -p ~/backups/robot-dog

# 备份主数据库
cp ~/.local/share/RobotDogControl/main.db \
   ~/backups/robot-dog/main_$(date +%Y%m%d_%H%M%S).db
```

#### 工程备份

**方式1: 手动复制整个工程文件夹**

```bash
# 备份单个工程
cp -r ~/Documents/RobotDogControlProjects/工程名_uuid \
      ~/backups/robot-dog/工程名_uuid_$(date +%Y%m%d)

# 备份所有工程
tar -czf ~/backups/robot-dog/projects_$(date +%Y%m%d).tar.gz \
         ~/Documents/RobotDogControlProjects
```

**方式2: 使用导出功能**

在前端界面中使用"导出工程"功能，会生成 `.rdcp` 文件。

### 6.2 自动备份脚本

创建 `backup.sh`:

```bash
#!/bin/bash

BACKUP_DIR=~/backups/robot-dog
DATE=$(date +%Y%m%d_%H%M%S)

mkdir -p "$BACKUP_DIR"

# 备份主数据库
cp ~/.local/share/RobotDogControl/main.db \
   "$BACKUP_DIR/main_$DATE.db"

# 备份所有工程
tar -czf "$BACKUP_DIR/projects_$DATE.tar.gz" \
         ~/Documents/RobotDogControlProjects

# 保留最近 30 天的备份
find "$BACKUP_DIR" -name "*.db" -mtime +30 -delete
find "$BACKUP_DIR" -name "*.tar.gz" -mtime +30 -delete

echo "备份完成: $DATE"
```

**设置定时任务（cron）**:

```bash
# 编辑 crontab
crontab -e

# 添加每天凌晨 2 点自动备份
0 2 * * * /path/to/backup.sh
```

### 6.3 恢复数据

**恢复主数据库**:

```bash
# 停止服务
./start.sh --stop

# 恢复数据库
cp ~/backups/robot-dog/main_20260113_020000.db \
   ~/.local/share/RobotDogControl/main.db

# 重启服务
./start.sh
```

**恢复工程**:

```bash
# 解压备份
tar -xzf ~/backups/robot-dog/projects_20260113.tar.gz -C ~/Documents/
```

## 7. 常见问题

### 7.1 服务无法启动

**问题**: 执行 `./start.sh` 后服务无法启动。

**排查步骤**:

1. 检查端口占用：

```bash
# Linux/macOS
lsof -i :3000
lsof -i :5173

# Windows
netstat -ano | findstr :3000
netstat -ano | findstr :5173
```

2. 查看日志：

```bash
tail -f logs/backend.log
tail -f logs/frontend.log
```

3. 检查依赖：

```bash
cd app/backend && npm list
cd app/frontend && npm list
```

### 7.2 数据库初始化失败

**问题**: `npm run init-db` 报错。

**解决方案**:

1. 确认 TypeScript 已编译：

```bash
cd app/backend
npm run build
```

2. 检查数据目录权限：

```bash
ls -la ~/.local/share/RobotDogControl
```

3. 手动创建目录：

```bash
mkdir -p ~/.local/share/RobotDogControl
mkdir -p ~/Documents/RobotDogControlProjects
```

### 7.3 机器人连接失败

**问题**: 无法连接到机器人。

**排查步骤**:

1. 检查网络连通性：

```bash
ping 192.168.1.110  # 替换为机器人 IP
```

2. 测试 SSH 连接：

```bash
ssh firefly@192.168.1.110
```

3. 检查本地 IP 配置是否正确

4. 查看机器人控制日志

### 7.4 Python 脚本执行失败

**问题**: 动作执行时报 Python 错误。

**解决方案**:

1. 检查 Python 版本：

```bash
python3 --version
```

2. 安装缺失的依赖：

```bash
pip3 install paramiko
```

3. 检查 SDK 库文件是否存在：

```bash
ls -la app/robot-control/lib/so/x86_64/
```

### 7.5 前端无法访问后端 API

**问题**: 前端请求后端 API 返回 404 或 CORS 错误。

**解决方案**:

1. 确认后端服务已启动：

```bash
curl http://localhost:3000/health
```

2. 检查前端代理配置（`vite.config.ts`）

3. 检查后端 CORS 设置（`app/backend/src/index.ts`）

## 9. 安全建议

### 9.1 网络安全

- 使用防火墙限制后端端口（3000, 3001）的访问
- 不要将后端服务直接暴露到公网
- 使用 HTTPS（生产环境）

### 9.2 SSH 凭证管理

- 不要在代码中硬编码 SSH 密码
- 使用环境变量或配置文件存储凭证
- 考虑使用 SSH 密钥认证替代密码认证

### 9.3 数据安全

- 定期备份数据库
- 限制数据目录的访问权限：

```bash
chmod 700 ~/.local/share/RobotDogControl
```

- 不要将敏感数据提交到版本控制系统

### 9.4 更新维护

- 定期更新 Node.js 和 npm
- 定期更新项目依赖：

```bash
cd app/backend && npm update
cd app/frontend && npm update
```

- 关注安全公告和漏洞修复

## 附录

### A. 系统服务配置（Linux）

创建 systemd 服务文件 `/etc/systemd/system/robot-dog.service`：

```ini
[Unit]
Description=Robot Dog Control System
After=network.target

[Service]
Type=simple
User=youruser
WorkingDirectory=/path/to/robot-dog
ExecStart=/path/to/robot-dog/start.sh --start
ExecStop=/path/to/robot-dog/start.sh --stop
Restart=on-failure

[Install]
WantedBy=multi-user.target
```

**启用服务**:

```bash
sudo systemctl enable robot-dog
sudo systemctl start robot-dog
sudo systemctl status robot-dog
```
