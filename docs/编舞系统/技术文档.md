## 1. 项目概述

本项目旨在开发一个可视化的机器狗控制系统，支持多机器狗协同控制、动作编排和实时监控。系统采用前后端分离的架构，提供类似视频编辑器的时间轴界面，用户可以通过拖拽、编辑关键帧的方式编排机器狗的动作序列。

### 1.1 核心功能

- **多机器狗控制**：支持同时控制多个机器狗执行不同或协同的动作
- **时间轴编辑**：提供可视化的时间轴编辑器，支持关键帧、动作层、音频层等
- **实时预览**：实时显示机器狗状态和动作预览
- **工程管理**：支持工程的保存、导入、导出和分享
- **跨平台支持**：支持 Windows、Ubuntu 等多平台运行

### 1.2 机器狗型号

- **品牌**：AgiBot
- **型号**：基于 AgiBot SDK 的四足机器狗
- **支持动作**：站立、趴下、移动、跳跃、前跳、后空翻、握手、姿态控制等

### 6.2 类设计

#### 6.2.1 `RobotDog` 基类

**功能**：封装 AgiBot SDK 的基础接口。

**主要方法**：

- `__init__(name, robot_ip, local_ip, local_port)`：初始化机器狗连接
- `get_current_ctrl_mode()`：获取当前控制模式
- `stand_up(duration)`：站立
- `lie_down(duration)`：趴下
- `attitude_control(roll_rate, pitch_rate, yaw_rate, height_vel)`：姿态控制
- `move(vx, vy, yaw_rate)`：移动
- `jump(duration)`：跳跃
- `front_jump(duration)`：前跳
- `back_flip(duration)`：后空翻
- `shake_hand(duration)`：握手
- `_safe_action(action, action_name, interval)`：安全执行动作（带重试）

#### 6.2.2 `CrazyRobotDog` 扩展类

**功能**：继承 `RobotDog`，提供更高级的动作封装。

**主要方法**：

- `lean_left(duration, reset)`：左倾
- `lean_right(duration, reset)`：右倾
- `nod_up(duration, reset)`：抬头
- `nod_down(duration, reset)`：低头
- `max_height(duration, reset)`：最大高度
- `min_height(duration, reset)`：最小高度
- `rotate_clockwise(duration)`：顺时针旋转
- `rotate_counterclockwise(duration)`：逆时针旋转
- `turn_around(angle)`：转身（指定角度）

### 6.3 并发控制

#### 6.3.1 `execute_concurrently` 函数

**功能**：并发执行多个机器狗的动作。

**参数**：
- `*actions`：多个动作函数引用
- `_interval`：动作之间的微小延时（避免网络拥堵）

**示例**：

```python
execute_concurrently(
    lambda: dog1.stand_up(),
    lambda: dog2.stand_up(),
    _interval=0.1
)
```

### 6.4 日志系统

**功能**：记录动作执行的日志，格式为 ISO 8601。

**格式**：

```
[时间戳] [标识] [机器狗名称] 动作名称 -> 结果
```

**示例**：

```
[2025-12-16T14:23:45.123456+08:00] [+] [131] standUp() -> 0
[2025-12-16T14:23:45.234567+08:00] [-] [131] move(1.0, 0, 0) -> 0x3013
```

### 6.5 错误处理

#### 6.5.1 自动重试机制

`_safe_action` 方法会自动重试失败的动作，直到成功为止。

#### 6.5.2 错误码说明

| 错误码 | 含义 |
|--------|------|
| 0 | 执行成功 |
| 0x3007 | 状态机切换失败 |
| 0x3009 | 电机角度超限 |
| 0x3010 | 电机失能 |
| 0x3011 | 电机故障 |
| 以下文档：

- **机器狗 SDK API**: [机器狗SDK_API定义.md](./机器狗SDK_API定义.md) - Python SDK 的底层 API 定义
- **后端 REST API**: [API接口文档.md](./API接口文档.md) - 完整的 HTTP API 接口文档
| 0x3013 | 速度命令过大 |

## 7. API 接口文档

详见 [机器狗SDK_API定义.md](./机器狗SDK_API定义.md)。

### 7.1 核心方法

#### 7.1.1 初始化

```python
app = mc_sdk_zsl_1_py.HighLevel()
app.initRobot(local_ip, local_port, dog_ip)
```

#### 7.1.2 控制模式查询

```python
mode = app.getCurrentCtrlmode()
```

**返回值**：
- `0`：阻尼模式，设备未开启
- `1`：站立状态/打招呼状态
- `10`：设备趴下时触发电机自由状态
- `18`：移动状态
- `21`：动作状态（姿态模式、跳跃模式、双腿站立等）
- `51`：趴下状态

#### 7.1.3 基础动作

| 方法 | 参数 | 说明 |
|------|------|------|
| `standUp()` | 无 | 站立 |
| `lieDown()` | 无 | 趴下 |
| `passive()` | 无 | 阻尼（紧急趴下）|
| `move(vx, vy, yaw_rate)` | vx: 前向速度<br>vy: 侧向速度<br>yaw_rate: 角速度 | 移动 |
| `jump()` | 无 | 原地跳 |
| `frontJump()` | 无 | 向前跳 |
| `backflip()` | 无 | 后空翻 |
| `shakeHand()` | 无 | 打招呼 |

#### 7.1.4 姿态控制

```python
app.attitudeControl(roll_rate, pitch_rate, yaw_rate, height_vel)
```

**参数范围**：
- `roll_rate`：∈ (-0.6, 0.6) rad/s
- `pitch_rate`：∈ (-0.6, 0.6) rad/s
- `yaw_rate`：∈ (-0.6, 0.6) rad/s
- `height_vel`：∈ (-0.5, 0.5) m/s

#### 7.1.5 移动控制

```python
app.move(vx, vy, yaw_rate)
```

**参数范围**：
- `vx`：∈ (-3.0, -0.05) ∪ (0.05, 3.0) m/s
- `vy`：∈ (-1.0, -0.1) ∪ (0.1, 1.0) m/s
- `yaw_rate`：∈ (-3.0, -0.02) ∪ (0.02, 3.0) rad/s

## 8. 示例代码

### 8.1 基础示例：站立

```python
from lib.api import CrazyRobotDog

# 初始化131号狗
dog_131 = CrazyRobotDog(
    name='131',               # 名称，用于日志输出
    robot_ip='192.168.0.2',   # 机器人IP
    local_ip='192.168.0.214', # 本地IP
    local_port=10131          # 本地端口，一般设置为 10000 + 狗狗编号
)

# 让狗站立（大约花费4.5秒）
dog_131.stand_up()
```

### 8.2 单狗舞蹈示例

```python
from lib.api import CrazyRobotDog
import time

DOGS_CONFIG = {
    "131": ("192.168.1.110", 10131),
}

LOCAL_IP = "192.168.1.105"

dog1 = CrazyRobotDog(
    name="131",
    robot_ip=DOGS_CONFIG["131"][0],
    local_ip=LOCAL_IP,
    local_port=DOGS_CONFIG["131"][1],
)

# 站立
dog1.stand_up(0)
time.sleep(0.8)

# 点头动作
dog1.nod_up(2)
dog1.nod_down(2)
dog1.max_height(2)
dog1.nod_up(2)

# 旋转
for _ in range(3):
    dog1.rotate_clockwise()
    dog1.rotate_counterclockwise()

# 转身并后空翻
dog1.turn_around(angle=90)
time.sleep(0.8)
dog1.back_flip()

# 更多旋转
for _ in range(8):
    dog1.rotate_counterclockwise()
    dog1.rotate_clockwise()

# 高度变化
dog1.min_height(1)
dog1.max_height(2)
dog1.nod_down(2)

# 跳跃
dog1.jump()

# 快速高度变化
for _ in range(14):
    dog1.max_height(0.3)
    dog1.min_height(0.3)

# 握手
dog1.shake_hand()
time.sleep(1)
```

### 8.3 多狗并发控制

```python
from lib.api import CrazyRobotDog, execute_concurrently

dog1 = CrazyRobotDog(name="131", robot_ip="192.168.1.110", local_ip="192.168.1.105", local_port=10131)
dog2 = CrazyRobotDog(name="47", robot_ip="192.168.1.116", local_ip="192.168.1.105", local_port=10047)

# 两条狗同时站立
execute_concurrently(
    lambda: dog1.stand_up(),
    lambda: dog2.stand_up(),
    _interval=0.1
)

# 同步动作
execute_concurrently(
    lambda: dog1.jump(),
    lambda: dog2.jump(),
    _interval=0.05
)
```

## 9. 数据库设计

本项目采用**主数据库 + 工程数据库**分离的架构设计。详细的数据库设计请参考：

- **完整数据库设计**: [数据库设计文档.md](./数据库设计文档.md)

### 9.1 技术选型

- **数据库**：SQLite 3
- **Node.js 库**：sqlite3 5.1.7
- **原因**：
  - 轻量级，无需单独部署数据库服务
  - 数据存储在本地文件，便于工程管理
  - 支持跨平台
  - 外键支持已启用

### 9.2 数据库架构概述

采用**主数据库 + 工程数据库**分离的架构：

**主数据库 (main.db)**:
- 存储全局信息（用户、工程索引）
- 位置：`~/.local/share/RobotDogControl/main.db` (Linux)

**工程数据库 (project.db)**:
- 每个工程独立的数据库
- 位置：`~/Documents/RobotDogControlProjects/工程名_uuid/project.db`

**优点**：
- 工程隔离，互不影响
- 便于工程导入/导出
- 避免单一数据库过大
- 支持工程级别的备份和恢复

详细的表结构、字段说明、索引设计等请查看 [数据库设计文档.md](./数据库设计文档.md)。

### 9.3 主要数据表（概览）

**主数据库 (main.db)**:
- `users`: 用户表
- `project_index`: 工程索引表

**工程数据库 (project.db)**:
- `project_config`: 工程配置表
- `robots`: 机器人表
- （预留）时间轴相关表

## 10. 时间轴编辑器设计

### 10.1 功能需求

仿照视频编辑器的时间轴，支持以下功能：

1. **多图层管理**：
   - 音频层
   - 关键帧层
   - 动作层
   
2. **关键帧编辑**：
   - 添加/删除关键帧
   - 拖拽关键帧调整时间
   - 修改关键帧参数

3. **动作块编辑**：
   - 添加动作块（如行走、跳跃、表演）
   - 拖拽调整动作块的开始时间和结束时间
   - 复制/粘贴/删除动作块
   - 缩放动作块（调整时长）

4. **时间轴控制**：
   - 播放/暂停
   - 时间刻度缩放
   - 时间轴拖动

### 10.3 动作块数据结构

```typescript
interface ActionBlock {
    uuid: string;           // UUIDv7
    layerUuid: string;      // 所属图层
    robotUuid?: string;     // 关联机器人
    actionType: 'perform' | 'walk' | 'wait' | 'jump' | 'flip' | 'shake_hand';
    startTime: number;      // 开始时间（秒）
    endTime: number;        // 结束时间（秒）
    parameters: {           // 动作参数
        speed?: number;     // 速度
        direction?: number; // 方向
        expression?: string;// 表情
        [key: string]: any; // 其他参数
    };
}
```

### 10.4 关键帧数据结构

```typescript
interface Keyframe {
    uuid: string;           // UUIDv7
    layerUuid: string;      // 所属图层
    robotUuid?: string;     // 关联机器人
    time: number;           // 关键帧时间点（秒）
    parameters: {           // 姿态参数
        rollRate?: number;
        pitchRate?: number;
        yawRate?: number;
        heightVel?: number;
        [key: string]: any;
    };
}
```

### 10.5 交互流程

1. **添加动作块**：
   - 用户从指令面板拖拽动作到时间轴
   - 系统在指定时间点创建动作块
   - 记录到数据库

2. **编辑动作块**：
   - 拖拽调整开始/结束时间
   - 双击打开参数编辑面板
   - 修改后保存到数据库

3. **复制/粘贴**：
   - 选中动作块，Ctrl+C 复制
   - Ctrl+V 粘贴到指定位置
   - 生成新的 UUID

4. **播放预览**：
   - 解析时间轴数据
   - 按时间顺序发送指令到机器狗
   - 实时显示机器狗状态

### 11.4 工程导入/导出

#### 11.4.1 导出工程

**流程**：
1. 选择要导出的工程
2. 用户选择导出选项：
   - [ ] 包含音频文件
   - [ ] 包含备份文件
   - [ ] 包含缓存文件（一般不需要）
3. 打包工程文件夹为 `.rdcp`（Robot Dog Control Project）或 `.zip` 文件
4. 保存到用户指定位置

**导出文件结构**：
```
my_dance_project.rdcp (zip 格式)
├── project.json              # 必需
├── project.db                # 必需
├── audio/                    # 可选
└── exports/                  # 可选
```

#### 11.4.2 导入工程

**流程**：
1. 选择 `.rdcp` 或 `.zip` 文件
2. 解压到临时目录
3. 验证 `project.json` 和 `project.db` 完整性
4. 检查版本兼容性（如需要则执行数据库迁移）
5. 生成新的工程文件夹名称（避免冲突）
6. 复制到 `projects/` 目录
7. 在主数据库 `main.db` 的 `project_index` 表中添加记录
8. 重建缓存目录

**冲突处理**：
- 如果工程 UUID 已存在，提示用户：
  - 替换现有工程
  - 导入为新工程（生成新 UUID）
  - 取消导入

## 12. 错误处理

### 12.1 网络错误

**问题**：机器狗连接失败或超时。

**处理**：
- 自动重试连接（最多 3 次）
- 显示错误提示给用户
- 记录错误日志

### 12.2 动作执行错误

**问题**：动作执行返回非 0 错误码。

**处理**：
- `_safe_action` 方法自动重试
- 记录错误日志
- 如果连续失败 10 次，提示用户检查机器狗状态

### 12.3 状态切换错误

**问题**：在不允许的状态下切换动作（如移动中切换到跳跃）。

**处理**：
- 先切换到安全状态（如站立）
- 再执行目标动作
- 前端提供状态检查

### 12.4 并发冲突

**问题**：多个线程同时控制同一机器狗。

**处理**：
- 使用线程锁保护关键代码
- 队列化动作指令

A3：使用 `execute_concurrently` 函数并发执行动作。
