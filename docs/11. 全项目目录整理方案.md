# 11. 全项目目录整理方案

本文档直接作为本仓库目录整理的执行清单。

截至 `2026-03-31`，仓库内已经同时存在以下几套风格：

- 顶层项目目录仍以 `app/` 聚合，但其中又混有前端、后端、手机端、机器狗端、公共库
- 同类概念混用 `前端/后端`、`modules/features`、`路由/服务`、中英文目录名
- 构建产物、缓存、日志、抓包文件、安装包与源码目录混放
- 个别目录名过弱，例如 `other/`、`src/other/`、顶层 `services/`

该项目为自用项目，不考虑向后兼容，因此这次整理按“统一命名、统一层级、一次到位”为原则。

## 整理目标

- 仓库顶层统一为 `apps/`、`packages/`、`deploy/`、`third_party/`、`artifacts/`、`archive/`、`var/`
- 所有源码目录统一英文命名，中文仅保留在文档、注释、界面文案中
- 业务域统一叫 `features`，不再混用 `modules`
- 启动装配统一叫 `app`
- 基础设施统一叫 `infra`
- 跨业务共享统一叫 `shared`
- 构建产物、缓存、日志、抓包、安装包不再影响源码结构设计

## 命名规则

- 目录统一使用英文，推荐 `kebab-case`
- `modules` 全部改为 `features`
- `services` 不再作为 `src` 顶层兜底目录
- `other` 不允许继续新增
- 前端与移动端统一使用 `src/app + src/features + src/shared`
- 后端与 Python 服务统一使用 `src/app + src/features + src/infra + src/shared`
- Python 包导入名 `sparkrobot_common` 保持不变
- React Native 应用名 `RobotPhone` 保持不变
- 原生工程名、包名、Bundle Identifier、`app.json` 显示名不因为目录整理而修改

## 执行顺序

建议按以下顺序整理，避免一次性打散过多引用：

1. 先清理缓存、构建产物、日志、`egg-info`
2. 再做仓库顶层目录迁移
3. 同步修改所有脚本、文档、README、部署文件中的路径
4. 再改每个子项目 `src` 的内部结构
5. 最后统一 import 路径与别名
6. 每个子项目单独跑一遍校验
