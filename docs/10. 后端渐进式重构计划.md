## 当前仍然需要重构的部分

### P0：继续拆 `WebSocketService`

这仍然是当前最大的复杂度来源。

当前问题：

- `src/modules/websocket/service.ts` 仍然是 WebSocket 依赖装配中心，即使体量已收缩到 `196` 行左右。
- service 主类里的仓库访问代理已基本移除，但构造阶段仍然依赖较多闭包 / bind 形式向各 gateway 注入能力。
- `WebSocketService` 仍然是连接注册表、宿主、消息发送入口和命令网关的集中持有者。
- 剩余弱类型问题已不再主要集中在 `WebSocket` 主链路实现文件，而是更多转移到基础设施与外部集成层，例如 `core/logger/index.ts`、`bootstrap/create-app.ts`、`modules/系统/routes.ts`、`modules/大模型交互/asr-service.ts`、`modules/大模型交互/llm-service.ts` 等。

建议拆分方向：

- `connection-registry.ts`
- `ui-auth.ts`
- `message-router.ts`
- `robot-command-gateway.ts`
- `audio-session-manager.ts`
- `audio-route-gateway.ts`
- `conversation-gateway.ts`

### P2：继续收口依赖注入和循环依赖

虽然 `bootstrap` 已经存在，但依赖方向还没有完全理顺。

当前问题：

- `create-app-context.ts` 对外装配已经不再依赖一长串 `setXxxService()`，但 `WebSocketService` 内部仍通过较多运行时闭包 / bind 向各 gateway 暴露依赖。
- 编舞执行链已经切到构造注入的小接口，但 `WebSocketService` 自身仍是当前最主要的依赖集中点。

目标：

- 能构造时注入的依赖尽量在构造时注入。
- 必须晚绑定的能力改成更明确的小接口，而不是直接相互持有整个大服务。
- 主要模块应能在测试中独立实例化，不依赖隐含初始化顺序。

### P1：继续收口服务层错误模型与类型边界

这已经进入可以系统治理的阶段。

当前问题：

- 非测试代码里仍然存在较多 `any`。
- `WebSocket` 主链路实现文件里的 `any` 已基本清空，下一批高优先级热点转移到 `logger`、`create-app.ts`、`system/routes.ts`、`asr-service.ts`、`llm-service.ts`、`机器人管理/service.ts` 等基础设施和集成层。
- 公共类型虽然已从 `any` 收口到 `unknown`，但 service 层对这些 `unknown` 的领域化收窄仍然不够系统。
- 控制器层虽然已经统一 HTTP 错误包装，但 service 层仍主要依赖字符串消息驱动状态映射。

目标：

- 继续把高频领域错误从“字符串消息”收口成更稳定的错误类型。
- 清理主要路径上的 `any`。
- 继续把剩余高频参数解析和响应模板抽成基础设施。

### P2：后续再拆 `机器人服务`

`src/modules/机器人管理/service.ts` 当前仍然职责偏多：

- 仓库读写
- SSH 初始化
- 连通性检测
- WebSocket 命令代理
- 安装包推送
- 音频路由配置读写

这不是当前最急，但会是 `WebSocketService` 之后的下一块重点。

## 不做的事

- 不整体改写为 NestJS。
- 不把 WebSocket 第一轮直接改成 Socket.IO。
- 不为了“更现代”而整体挪目录或全量重命名。
- 不在没有明确收益的情况下追求一次性清空所有 `any`。
- 不在同一轮同时修改协议、数据库层、WebSocket 路由和前端联动。

## 重构原则

1. 先删遗留基础设施，再拆当前最大复杂度热点。
2. 先收口依赖方向，再做风格统一。
3. 每次只推进一个高风险问题，避免重构项叠加。
4. 第一轮继续尽量保持 REST 路由和 WebSocket 消息协议稳定。
5. 每完成一个阶段，都要跑 `npm run lint`、`npm run typecheck`、`npm test`。

## 建议的后续阶段顺序

### 阶段 A：移除旧同步数据库层（已完成）

目标：

- 彻底结束双数据库访问模型并存状态。

内容：

1. 为系统路由补异步统计依赖。
2. 将启动期机器人离线重置迁移到异步 `robot repository`。
3. 将默认角色初始化迁移到异步 `role repository` 或独立 bootstrap 初始化函数。
4. 删除 `src/core/database/` 旧实现及其引用。

验收：

- 运行时代码不再依赖 `Atomics.wait`。
- 应用启动不再实例化 `DatabaseService`。
- 系统状态接口行为不变。

### 阶段 B：拆 `WebSocketService`

目标：

- 将 WebSocket 从巨石类拆成多个可组合部件。

内容：

1. 抽连接注册与路由分发。
2. 抽 UI 鉴权。
3. 继续扩展已抽出的机器人命令网关。
4. 抽音频会话管理。
5. 抽对话输入编排。
6. 将大部分 setter 注入收口为构造依赖或更小接口。

验收：

- `websocket/service.ts` 显著缩小。
- 新增机器人指令时不再复制样板代码。

### 阶段 C：文件 I/O、错误模型、类型边界收口

目标：

- 让剩余基础设施风格统一。

内容：

1. 清掉 `server.ts`、`logger` 等剩余同步文件 I/O / 启动阻塞点。
2. 抽统一错误类型和错误响应映射。
3. 收口控制器重复样板。
4. 按高频路径清理 `any`。
